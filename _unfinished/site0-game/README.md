# PRIM3 Site 0 — the Kimi build

Recovered 2026-08-19 from the Kimi deployment, mirrored
whole, and made to run offline. **This is the thing that was actually
built** — not the drawings, not the Drive zip. Three pieces:

| | |
| --- | --- |
| `index.html` | **Interactive Design Bible** — the nine-level stack, 25 L1 programme zones, interior concepts, material and lighting doctrine, the Marble pipeline |
| `game/` | **Playable FPS build** — *"L1 Center Drive-Through · Three-Agent Test"*. WASD, sprint, jump, overview map, respawn, and three agents: walk, drive, taxi a plane on the ground. Loads `assets/prim3_site0_l1_squared.glb`. |
| `viewer/` | **Splat world viewer** — navigable Gaussian-splat worlds for L3 and B3 |

Shelved rather than served: 54 MB has no business loading for somebody
reading the résumé page, and the deploy strips `_unfinished/`. To put it
on the site, move it out and add a route.

## Running it

```
python3 -m http.server 8080     # from this directory
# bible  → http://127.0.0.1:8080/
# game   → http://127.0.0.1:8080/game/index.html
# viewer → http://127.0.0.1:8080/viewer/index.html
# game with the exterior shell → .../game/index.html?shell=1
#   (run `python3 tools/unpack_shell.py` once first)
```

`probe/` is the floor-coverage harness — it loads the same model with the
same `classify()` rules the game uses and raycasts down at every mission
waypoint, every lift pad and a 24×24 grid on each level, so "can you stand
here" is answered by measurement rather than by walking around hoping.

```
node probe/run.mjs http://127.0.0.1:8080/probe/probe.html
```

Verified: **zero failed requests, zero page errors, canvas renders.**

Three.js 0.166.1, its three addons and Spark 0.1.10 were on jsdelivr; they
are now vendored under `vendor/` and the import maps rewritten, so nothing
here depends on a CDN or on the Kimi share link staying alive. The
`kimi.com/sdk-seed.js` tag was dropped — it is Kimi's own page telemetry
and has no role in the build.

## The interior inside the perfect shell

Measured first, because the interior turned out to need no moving at all:

| axis | shell | building | fill |
| --- | --- | --- | --- |
| X | 0.9562 | 0.9590 | 100.3% |
| Y | 0.4720 | 0.4416 *(above ground)* | 93.6% |
| Z | 0.9832 | 0.8958 | 91.1% |

Only two nodes stick out of the shell — `L1_ROAD_NORTH_GATE` and
`L1_ROAD_SOUTH_GATE`, the north and south **aprons**, which are outdoor
pavement and belong outside the building by definition. Everything else is
inside, five more nodes by under 0.001 which is float rounding.

So the shell is fitted to the interior, not the interior to the shell.
`tools/fit_shell_to_interior.py` records why in full, and the short version
is this: `game/index.html` hard-codes the lift shafts and the mission
waypoints in **model coordinates** —

```
SHAFTS  A:{x:-0.065*SCALE, z:0.27*SCALE, …}
PTS     gate:(0,-0.28*SCALE)  fork:(0,0.255*SCALE)  …
```

— so moving the geometry to suit a skin would leave every lift opening onto
empty air and every objective in the wrong room. The game would still run
and would be quietly broken, which is worse than not running.

The fit is a translation of **+0.0448 in Z** (the building sits that far
north of the shell's centre) and a scale of **1.004 in X and Z**, so the
building is *inside* the skin rather than flush with it — 0.77 m of clearance
on a 261 m facade, which also stops the faces z-fighting. Y is untouched:
the shell already stands on y=0 and is taller than the interior, and the
basements are below y=0 and outside it on purpose.

Verified: every above-ground node except the two aprons is inside the fitted
shell.

### Cut to the shell's coordinates

*"Cut every excess piece of the Kimi build and make it conform exactly to the
shell coordinates of the perfect glb."*

**The obvious way to do that does not work, and it is worth knowing why.**
Clipping to the shell's hollow interior needs an inside/outside test, and that
question has no answer for this mesh: the Tripo export is **not watertight** —
**283,418 of its 2,940,568 edges (9.64%) are boundary edges**, used by one
triangle instead of two. Ray parity needs a closed surface; with holes the ray
leaves through one and the parity flips. Run that way, the test scored road
markings at the dead centre of the building as **0% inside**. Nothing was cut
on that basis.

What *is* well defined from a mesh with holes is its **silhouette** at a given
height — it needs only vertex positions. `tools/conform_to_shell.py` clips every
interior vertex to the silhouette of the 64-band slice it sits in, so the
building's outline follows the shell's as it tapers, and anything past it is
cut off. Below ground the shell has no opinion, so basements are clipped to the
widest band instead — inside the building's plan without pretending the shell
encloses them.

**48 nodes were cut.** The worst:

| node | cut back |
| --- | --- |
| `FREIGHT_HEAVY_LIFT_CORE_EAST_02/03` | 83.8 m |
| `SHELL_PANEL_REVEAL_01` *(Kimi's own shell)* | 47.0 m |
| `L1_GROUND_DEFENSE_LINTEL` | 42.6 m |
| `VERTICAL_PASSENGER_CORE_D_02/03` | 39.1 m |
| `L4_ISLAND_PEDESTAL` | 26.7 m |
| `L2_BUSINESS_AVIATION_FLOOR` | 14.5 m |

The tall lift cores dominate because they run the building's full height and
the shell narrows to about 22 m near the top — a 0.7 m post at x = +29 m is
84 m outside the silhouette *up there* while being comfortably inside lower
down. Clamping tapers them rather than truncating them.

**What it broke, and the fix.** Cutting the south apron back to the silhouette
moved its edge from −122.5 m to −104.8 m, and the spawn sat at −120.1 m — 15 m
off the end, in mid-air. Caught by the probe, not by looking. The spawn is now
−101.0 m, 3.8 m inside the new edge.

Verified after: every mission waypoint has ground, all 41 lift stops still land,
basement coverage unchanged at 86–92%, and the section through the centre is
**identical level for level to before the cut** — checked by running the same
test on the pre-cut model rather than assuming.

### L1 was under it, and six nodes stuck out of it

Two corrections after walking the build.

**L1 was underground.** The fit had aligned the shell's *bounding box* base with
the L1 datum, but the Tripo model carries a plinth below its own floor, and the
two are 2.52 m apart. So L1's floor sat 2.52 m below the shell's floor, which
put the player's eye — 1.86 m standing on the L1 road — underneath it.
`tools/measure_shell_floor.py` finds the floor by sampling columns through the
mesh and taking the median of the lowest surface; the shell is now lowered onto
it, and re-measures at a median −0.00 m. A translation, not a scale — the shell
is still 1,024,579 vertices.

**Six nodes broke the skin.** Every one was smaller than the envelope and
simply misplaced, so `tools/fit_inside_shell.py` moves them the minimum
distance in X and Z and resizes nothing:

| node | was out by | moved |
| --- | --- | --- |
| `B4_INTERFACILITY_TRANSFER_HALL` | 35.50 m −X | +35.50 m X |
| `L1_ROAD_NORTH_GATE` | 25.02 m +Z | −25.02 m Z |
| `L1_ROAD_SOUTH_GATE` | 19.46 m −Z | +19.46 m Z |
| `B2_HIGH_BAY_0` / `_1` | 5.47 m −X | +5.47 m X |
| `B2_HIGH_BAY_3` | 5.46 m +X | −5.46 m X |

Re-verified after: the spawn still lands on the south apron, every mission
waypoint still has ground, basement coverage is unchanged at 86–92%, all 41
lift stops still land, zero page errors.

Two things measured and deliberately left alone. The interior is **3.3% taller
than the shell's clear height** — 69.90 m from L1 floor to L3 deck against
67.71 m — so with the floors aligned the L3 deck plate sits about 2.2 m proud
of the shell's deck; closing it needs a squash of the interior or a stretch of
the perfect model. And the shell's floor is a photogrammetric surface with
about ±0.5 m of unevenness (p25 −0.61, p75 +0.45), so in places it can sit just
above L1's road and show through.

### It ships, and it is the exterior you see

The first version of this put the shell behind `?shell=1` because it was 47 MB.
That was wrong, and the owner said so: what the page actually showed anyone
standing outside was the Kimi build's **own** remodelled shell —
`SHELL_MAIN_RECTANGLE` and three decorative bands, 2,420 vertices — which is
precisely the part of that build he had rejected. A perfect exterior nobody
would ever type a flag to see is not a perfect exterior.

`tools/pack-shell.sh` re-encodes it instead. **Nothing is decimated, welded,
quantised or retopologised:**

| | before | after |
| --- | --- | --- |
| vertices | 1,024,579 | **1,024,579** |
| triangles | 1,865,906 | **1,865,906** |
| surface area | 2.798625811 | **2.798625811** *(delta 8.4e-14, summation order)* |
| centroid | — | identical to nine decimals |
| positions missing | — | **zero** |
| the fit | translation + scale | carried through unchanged |
| bytes | 46,981,828 | **17,270,844** |

The only thing that changes is vertex *order*, which gltfpack rearranges for
cache locality with the indices remapped to match. Same surface, better
container: `EXT_meshopt_compression`, decoded by a 25 KB vendored module.

It loads **after** the interior and in the background, so the building is
walkable while the skin streams in, with a percentage in the corner. When it
lands, the remodelled shell is hidden — kept in the scene, because it is
2,420 vertices of collision geometry and raycasting a million-vertex mesh
every frame is not a thing you do. A perfect skin over a cheap collision proxy
is how this is supposed to work.

`?shell=0` skips it.

**Why not 7 MB.** `gltfpack -vpf -vn 8` gets it to 7,107,144 bytes — 2.4× smaller
again — and it looks free: positions stay float32, the triangle count is
identical. It is not free. It welds 94,113 vertices, moves the centroid in the
sixth decimal and changes the surface area by 0.007%. That is 0.3 mm on a 262 m
building and nobody could see it, which is exactly why doing it quietly would
be the wrong call. The flag is one line away in `tools/pack-shell.sh` if the
download ever matters more than the guarantee.

## Making it playable

Two defects, both found by measuring rather than by reading.

### 1. The rooms are floor plates, and treating them as walls sealed the building

Every node's height at `SCALE=273`:

```
  0.04 m   road markings
  0.10 m   the six L1 rooms
  0.82 m   every B1–B5 room
  2.73 m   the L2 room volumes
  4.91 m   the B-level enclosure rings
  6.01 m   the 11-piece L1 podium
  8.19 m   the L1 lintel (the roof over it)
 55.69 m   the hull
122–141 m  the lift and stair cores — 0.7 m posts, full height
```

The B1–B5 "rooms" are **0.82 m plates** — floor finish, not volumes. The old
code classified by a hand-written list of literal node names, and anything
not on the list was solid. So every one of those plates was an invisible
knee-high wall, and the basements were a minefield.

The list is gone. `classify()` measures each mesh and decides:

- taller than a 2 m step → **solid**, it stops you
- a named surface, or shorter than a step → **walkable**, you stand on it
- both, if it is both

That last one is the case the first attempt got wrong. The L1 podium is
6.01 m of mass with the drive-through cut through it: walkable-only and the
road loses its walls and you stroll out through the building. `collide()`
casts at waist height, so a slab you are standing on top of never blocks
you — only its flank does, and only while you are beside it.

The four vertical cores are the exception in the other direction: 0.7 m posts
sitting *inside* the lift-pad radius, so making them solid would trap the
player on the pad the moment `ride()` sets them down. They are neither.

Result — floor coverage probed on a 24×24 grid at every level:

| level | floor under the level |
| --- | --- |
| B1 | 89% |
| B2 | 92% |
| B3 | 86% |
| B4 | 91% |
| B5 | 88% |

The misses are the perimeter sample row landing exactly on the slab
boundary. Every mission waypoint and every lift pad has ground under it.

### 2. Nine of the 38 lift stops opened into thin air

`ride()` teleports the player to the shaft's x/z at the target level's height.
Probing every stop against the real triangles:

```
BAD  A  L2   drop 14.2 m      BAD  D  L3   drop 74.1 m
BAD  B  L2   drop 14.2 m      BAD  D  L4   drop 92.7 m
BAD  C  L2   drop 14.2 m      BAD  EW L2   drop 14.2 m
BAD  C  B5   NOTHING          BAD  EE L2   drop 14.2 m
BAD  D  L2   drop 14.2 m
```

Every L2 stop on every shaft, because all six shafts pass through the L1/L2
two-storey void — which is where they should pass, but a lift that opens
into a void is not a stop. D at L3 is past the flight deck's north edge, and
D at L4 has nothing under it at all.

The stop table is no longer asserted. `deriveStops()` raycasts each candidate
after the model loads: floor at the shaft centre is the landing, and where
there is none it searches a ring out to 12 m and opens onto the nearest floor
*beside* the shaft, which is what a lift lobby is. Eight of the nine come
back that way, at 4–8 m of offset.

The ninth does not. **L4 is not served by a lift** — the only L4 floor is the
penthouse, over 100 m west of any shaft — and the game no longer pretends it
is. That is a gap in the model, not in the code, and inventing a landing
would have meant inventing geometry.

Verified in the browser: all 37 remaining stops land on real floor, none more
than 0.8 m off the level height, zero page errors.

| A | B4 B3 B2 L1 L2 L3 |
| B | B4 B3 B2 B1 L1 L2 |
| C | B5 B4 B3 B2 B1 L1 L2 |

### 3. What a play-test agent found, and what came of it

A second agent drove the build with Playwright for 42 minutes and came back
with eleven defects. Its verdict was *playable-with-problems*. Every one of
them is now fixed except where noted.

**It caught one I had just introduced.** `classify()` returned
`{walk: !wall && …, solid: h > STEP}` — the wall flag *removed* walkability
without *granting* solidity, so any mesh named as a wall and under 2 m tall
was neither: a pass-through phantom. Live on `SHELL_PANEL_REVEAL` (1.09 m),
its twin, and `L4_ISLAND_ROOF_RING`. Naming a mesh as a wall was making it
less solid than not naming it. `solid: wall || h > STEP`.

**You could fall through L1 into a sealed B1.** Keyboard only, no cheats:
strafe west off the apron, then run north, and you drop 12 m into B1 with no
respawn and no way out. 148 grid cells at L1 had a >5 m drop within 4 m; the
worst measured −22.61 m, into B2.

The cause was the same as the next defect. `GROUND_PLANE` is built before the
GLB loads, so it never went through `classify()` and was in neither list.
`groundAt()` fell back to a hard-coded `-0.6` — invisible until the ray
happened to find a basement slab 12 m down, at which point you went through
the world. The ground plane is now in `walkables`, where it always belonged,
and outside the building you stand on it.

**There was no world boundary** — sprinting reached 1349 m out, standing on
nothing, HUD still reading "L1". Held at a 560 m perimeter now.

**Jump levitated and a tap did nothing.** Measured: tap Space, peak rise
0.00 m. Hold Space, +2.68 m against a predicted 1.04 m, then bouncing
`1.68, 1.42, 1.13, 1.35, 1.57, 1.79…` forever. The telemetry showed
`grounded=true, vy=4.4` at +1.32 m in the air — because
`if(Math.abs(g-feetY)<1.6) P.grounded=true` re-grounded the player up to
1.6 m *above* the floor, so the impulse re-applied every frame and releasing
snapped you back down instantly. Ground contact now means standing on a
surface or falling onto one, never floating above it, with a separate 1.2 m
step-up for kerbs.

**Movement was proportional to frame rate.** `Math.min(clock.getDelta(),0.05)`
*discards* time instead of catching up:

| render size | fps | walked in 5 s | intended |
| --- | --- | --- | --- |
| 1280×800 | 1.07 | 1.2 m | **4%** |
| 320×200 | 5.95 | 8.7 m | 29% |
| 128×96 | 11.49 | 17.4 m | 58% |

Real time is now accumulated and simulated in fixed 1/60 steps, capped at
0.5 s of catch-up. Drawing moved out of the physics step at the same time —
at 1 fps the accumulator runs 30 substeps, and repainting the minimap 30
times for one visible frame is 29 wasted repaints on the machine that can
least afford them.

**The minimap was drawn in the wrong coordinate space.** `mxX`/`mzY` divide
by `SCALE`, so they take world coordinates; `drawMap()` was passing model
units. The facility outline started at x=109.6 px on a 220 px canvas and ran
81 px off the right edge, so the plan was a clipped corner and the player
marker sat on it regardless of where you were.

**The armoured ramps were not a route.** The briefing says *take a side ramp
DOWN to B3*, but `B3_R1/R2_ARMORED_RAMP_LANDING` is a solid 23 m block
spanning B3 to L1 whose only walkable face is its top, and the well beside it
is neither walkable nor solid. So the waypoint left you standing at L1 and
the only way down was the 11 m fall above. The two ramps are now shafts —
`ride()` is exactly the mechanism a ramp needs, `deriveStops()` confirms both
ends, and the objective text says `[E/Q]`.

**The run could not be completed on the north route.** Only the B3 branch set
`missionDone`, so exiting via the north face — which the briefing lists as a
valid exit — dropped you into a permanent "TOUR" with RUN COMPLETE
unreachable. Both exits now finish the run and say which one you took.

**Key auto-repeat re-fired every keydown action** — holding M strobed
overview mode, constructing and disposing an `OrbitControls` per repeat.
Same shape on R, E and Q. `e.repeat` is now checked.

Not fixed, and why:

- **L4 is unreachable.** No shaft reaches it; its only floor is the penthouse,
  over 100 m west. A model gap — a landing would have to be invented.
- **Mouse-look is untested.** Pointer lock does not engage headless. The
  agent steered by writing `P.yaw`, the same variable the handler writes, so
  the handler itself has never been exercised.

What the agent confirmed working: boots with zero page errors across nine
runs, WASD in the right directions, sprint a real 1.9×, the drive-through a
properly bounded 13.2 m corridor with no leak, all three agents switching
with correct eye heights and speed ratios, R respawn exact, M overview,
every lift pad, and the objective HUD tracking and advancing.

### 4. The HUD only fitted a wide window

Five fixed-position panels, each sized to itself, each pinned to a corner.
Measured at four viewports:

| | before | after |
| --- | --- | --- |
| 1280×800 | clean | clean |
| 900×600 | objective over minimap, help over the agent row | clean |
| 600×400 | same two | clean |
| 390×844 | those plus objective over the clock | clean |

Fixed with a width budget on the centre panel, a scaled-down minimap, the help
line moved above the agent row rather than beside it, and — under 760 px —
the help text dropped, because the buttons under it say the same thing.

### 5. It was a slideshow on anything modest

A 2048 shadow map, a dozen point lights, antialiasing and a 1.6 pixel ratio.
On hardware that can carry it that is the right look; on hardware that cannot
it is one frame a second, and one frame a second is not playable. The
renderer now measures itself over 90 frames and steps down — pixel ratio,
then shadows, then the point lights — reporting where it landed in the HUD.
It never steps back up, because oscillating between two settings is worse
than sitting on the lower one.

## The splat worlds

`viewer/assets/` holds both tiers for L3 and B3.

The full-resolution files were left on the Kimi host on 2026-08-19, on the
reasoning that 96 MB in git was not worth it for assets the viewer loads on

the work moved from a shelved prototype to something being built on, and the

notice. Regenerating them needs an API key, credits, and — more to the point —
