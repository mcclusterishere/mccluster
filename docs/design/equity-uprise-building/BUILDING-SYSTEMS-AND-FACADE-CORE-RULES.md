# Equity Uprise — Building Systems + Facade Core Rules

> Status: **ACTIVE WHOLE-BUILDING AUTHORITY — IMPLEMENTATION NOT YET STARTED**
>
> Applies to B1, Floors 1–6 and Level 7. Read after Core V2 shared geometry and before any new facade, interior-envelope, MEP, IT, life-safety, service-detail or building-branding work.
>
> **Not for construction.** This is digital-twin / visualization / planning authority. Real construction requires licensed architectural and engineering design, site-specific codes, calculations, specifications and approvals.

## 1. Functional-building rule

The Equity Uprise building may no longer rely on rooms or colored volumes that merely *imply* a functioning building.

Every meaningful building system must be represented as a coherent chain:

**source / plant → vertical distribution → floor distribution → terminal / device / end use → monitoring / service access**

A system may be concealed in finished spaces, but its route and service logic must still exist in authority and be visible in appropriate service/technical views.

## 2. Preserve the proven building chassis

This pass may add enclosure depth, facade articulation, service infrastructure, support rooms, ceilings, soffits, shafts, equipment, devices, millwork and visible distribution.

It may **not casually move**:
- the 72' × 72' shell;
- finished-floor elevations;
- passenger elevator;
- service/freight elevator;
- Stair A;
- Stair B;
- shared slab openings;
- the current MEP/riser reservation;
- reconciled floor program geometry.

If a real systems conflict requires moving one of those, stop and issue a formal building-wide Core V2 revision instead of hiding the conflict.

## 3. No magic-infrastructure rule

A room that needs electricity, data, HVAC, plumbing, fire protection, AV, security or controls must have a documented physical support path.

Examples:
- a recording room needs power, data/AV and environmental support;
- a server rack needs power, network, cooling and service clearance;
- a restroom needs supply, sanitary and ventilation logic;
- a roof drain needs a storm route;
- a screen needs power/data;
- an access-controlled door needs power, reader/controller and network/control logic.

## 4. Nervous-system rule

The building must support at least these coordinated systems:
1. normal electrical power;
2. emergency / standby power concept;
3. lighting + lighting controls;
4. telecom / structured cabling;
5. AV / media distribution where required;
6. BAS / building controls / sensors;
7. security / access control / intercom / cameras where appropriate;
8. HVAC supply / return / exhaust;
9. domestic water;
10. sanitary drainage / vent;
11. storm / roof drainage / sump;
12. fire protection / sprinkler / standpipe concept;
13. fire alarm / notification / emergency communications;
14. vertical transportation support;
15. service / maintenance / housekeeping infrastructure.

## 5. Source-route-endpoint rule

Machine authority for every major system must identify:
- source or origin level;
- principal vertical route;
- floor branches served;
- representative endpoints;
- dependency on other systems;
- visibility mode;
- unresolved engineering items.

No system is complete merely because its source room exists.

## 6. Serviceability rule

Equipment must be placed as if someone eventually has to inspect, maintain, replace or isolate it.

Do not:
- block protected stairs;
- block elevator landings;
- fill required circulation with equipment;
- place racks against inaccessible walls with no service side;
- conceal valves/panels with no access concept;
- route major services through spaces that make no operational sense.

Exact code clearances remain unresolved until professional design, but **service access must be visibly plausible**.

## 7. Concealed-versus-exposed rule

Finished public rooms should not look like mechanical rooms merely to prove systems exist.

Use:
- ceiling devices, diffusers, grilles, access panels, receptacles, floor boxes and concealed routes in refined spaces;
- exposed ducts, trays, pipes, panels and equipment in B1, service corridors, selected media/technical spaces and dedicated system-view modes;
- cutaway / system-layer views when a concealed route needs to be inspectable.

## 8. Exterior-envelope rule

The building exterior must read as one designed institution, not stacked floor slabs.

The facade must establish:
- base / middle / crown composition;
- coherent glazing rhythm on all major elevations;
- opaque zones where core/service conditions require them;
- mullions / frames / spandrel or slab-edge logic;
- material continuity;
- real entrance hierarchy;
- roof/service screening;
- integrated Equity Uprise identity.

Facade work may reinterpret simplified exterior walls, but may not invalidate the Core V2 shell, floor elevations or protected core.

## 9. Interior-envelope rule

Every floor must read as a built interior rather than furniture on a slab.

At minimum, later implementation must coordinate:
- wall thickness and returns;
- real door openings / frames;
- interior glazing where appropriate;
- ceilings or intentionally exposed soffits;
- service access panels;
- built-in storage/support;
- lighting devices;
- HVAC terminals;
- power/data endpoints;
- life-safety devices;
- janitorial / support / service conditions where the floor needs them.

## 10. Branding rule

The exterior must visibly belong to Equity Uprise.

Canonical building identity uses:
- **E = U** as the principal architectural mark;
- **Equity Uprise** as the institutional wordmark.

Branding must be integrated into architecture and wayfinding, not pasted repeatedly across every surface.

## 11. Systems visibility / digital-twin rule

Future viewers should be able to support separable layers:
- Architecture
- Facade
- Electrical
- Lighting
- Data / Network / AV
- HVAC
- Plumbing
- Fire / Life Safety
- Security / Access
- Combined Services

The data model should therefore use stable system IDs and object IDs even before all visual modes are implemented.

## 12. Floor-program preservation rule

This pass supports existing Equity Uprise programs; it does not invent new program departments merely to justify mechanical or service objects.

Support rooms and closets may be added where functionally necessary, but must remain subordinate to the reconciled program and documented in floor-specific addenda before geometry is changed.

## 13. Exterior/interior coordination rule

A window, opaque panel, shaft, duct, pipe, cabinet, screen, sign or equipment item may not be placed independently of what is immediately behind or above/below it.

The facade, interiors and building systems are one coordinated model.

## 14. Realism gate

A future floor/building pass is not complete until it can answer:
- Where does power come from?
- Where does data come from?
- How is the space ventilated?
- Where does water come from and drain?
- How is fire protection distributed?
- How is the room monitored/controlled?
- How is equipment serviced?
- How does the exterior enclosure relate to the room behind it?

## 15. Current-pass boundary

This authority pass **does not yet modify geometry**.

It establishes the rules and machine-readable authority required for the subsequent facade/interior/services implementation pass.
