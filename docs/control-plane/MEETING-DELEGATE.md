# McCluster Owned Meeting Delegate

Status: implementation branch, 2026-09-22.

## Product rule

McCluster owns the meeting intelligence plane.

Third-party/open-source code may provide a replaceable transport implementation, but calendar policy, identity, scheduling, durable state, transcripts, debriefs, model reasoning, CRM/work integration, and approvals remain inside McCluster.

The initial engine contract is compatible with the Apache-2.0 Vexa API. The first audited upstream pin is `Vexa-ai/vexa-core` commit `37a920cd05116d6919186b0b9b4d564247d0e929`.

## Why this architecture

A universal meeting bot has two separate problems:

1. joining/capturing Meet, Zoom, Teams and similar browser meetings reliably;
2. deciding what the assistant knows, may say, may commit to, and what becomes durable operational truth.

The first problem can be bootstrapped from permissively licensed open source. The second is the McCluster product.

Core therefore exposes provider-neutral capabilities:

- `meeting.delegate.schedule`
- `meeting.delegate.join`
- `meeting.delegate.cancel`
- `meeting.delegate.status`
- `meeting.delegate.transcript`
- `meeting.delegate.session.get`

Interactive capabilities are declared but remain planned until the deployed engine passes live validation:

- `meeting.delegate.chat.read`
- `meeting.delegate.chat.send`
- `meeting.delegate.speak`

## Identity

The bot never impersonates Matthew.

Names are generated by Core:

- `McCluster AI Notes for Matthew`
- `McCluster AI Delegate for Matthew`
- `McCluster AI Observer for Matthew`

Delegate mode may later send an additional chat/voice disclosure after interactive controls pass validation.

## Owned flow

```
Google Calendar / Control Room
          |
          v
meeting.delegate.schedule
          |
          +--> ops_meeting_delegate_sessions
          |
          +--> ops_agent_jobs: meeting_delegate_dispatch
          |        |
          |        v
          |   self-hosted meeting engine on OVH/private network
          |        |
          |        +--> Meet / Zoom / Teams / Jitsi
          |
          +--> ops_agent_jobs: meeting_delegate_collect
                   |
                   +--> transcript from owned engine
                   +--> local Ollama / qwen3:8b
                   +--> durable debrief in Supabase
```

## Scheduling

`core.meeting.schedule` writes two durable jobs.

The dispatch job defaults to two minutes before the scheduled meeting.

The collection job defaults to five minutes after the scheduled end.

Both timings are configurable per request.

The existing Core runner already respects `ops_agent_jobs.run_after`, so there is no second cron/scheduler.

## Meeting credential containment

Scheduled meeting URLs and passcodes are treated as credentials.

Core hashes the meeting URL for correlation, encrypts the complete join target with AES 256 GCM using the OVH only `MCCLUSTER_MEETING_TARGET_KEY`, and stores only the ciphertext in the durable job input.

The target is decrypted in memory only when the dispatch or transcript collection job actually runs.

Changing the encryption key invalidates any meeting jobs still queued under the old key.

## Consent and authority

Transcription is fail-closed.

Notes/delegate mode requires `transcription_authorized=true`.

Recording is off by default and requires both `recording_enabled=true` and `recording_authorized=true`.

The durable session policy records that the AI has no independent:

- spending authority;
- contracting authority;
- legal admission authority;
- medical decision authority;
- academic commitment authority.

Anything outside the meeting brief is for Matthew to review.

## Interactive voice/chat

The Vexa ecosystem contains chat and speaking control surfaces, but open-core release behavior has changed across versions.

McCluster therefore defaults:

```
MCCLUSTER_MEETING_INTERACTIVE=0
```

Raw experimental tools fail closed until a deployed build passes a live end-to-end test.

This keeps the product honest: transcript capture can be production-ready without falsely claiming autonomous speaking.

## Engine configuration

Core expects a private/loopback meeting engine:

```
MCCLUSTER_MEETING_ENGINE_URL=http://127.0.0.1:18056
MCCLUSTER_MEETING_ENGINE_API_KEY=<server-side token>
MCCLUSTER_MEETING_TARGET_KEY=<long random Core-only encryption key>
MCCLUSTER_MEETING_PRINCIPAL_NAME=Matthew McCluster
MCCLUSTER_MEETING_INTERACTIVE=0
```

The API key stays server-side. It is never written into browser JavaScript, meeting session rows, transcripts, or job output.

## Source ownership bootstrap

Run:

```bash
bash scripts/bootstrap-owned-meeting-engine.sh
```

The script:

1. clones the upstream open-source source tree under `/srv/mccluster/vendor`;
2. pins the requested release/tag;
3. renames the upstream remote to `upstream`;
4. creates a local McCluster-owned branch;
5. does not start production services.

This keeps the main McCluster repo small while preserving a source-level copy that can be independently modified and pushed to a McCluster-owned remote.

## Long-term platform drivers

The meeting engine is intentionally replaceable.

Potential later native drivers:

- Google Meet Media API when its Developer Preview constraints no longer block ordinary external meetings;
- Zoom Meeting SDK / raw-data path for a native Zoom implementation;
- Microsoft Teams real-time media / calling bot path where account and tenant requirements fit;
- browser bot implementation for universal fallback.

The McCluster capabilities and data model do not change when a driver changes.

## Immediate acceptance path

1. Apply the meeting delegate migration.
2. Bootstrap/pin the owned meeting engine.
3. Bring the engine up privately on OVH.
4. Create a self-hosted API token.
5. Configure Core env.
6. Run `npm run test:meetings`.
7. Create a disposable Google Meet.
8. Call `meeting.delegate.join` with transcription authorization.
9. Admit the bot.
10. Verify speaker-attributed transcript.
11. Schedule a second disposable meeting through `meeting.delegate.schedule`.
12. Verify dispatch and collection jobs complete.
13. Verify Qwen debrief persists to `ops_meeting_delegate_sessions.summary`.
14. Only then test chat.
15. Only after chat passes, test audible speaking and set `MCCLUSTER_MEETING_INTERACTIVE=1`.
