# World News geography and event feeds — review branch

- Parent: #491, Docket 516R public archive and verified capstone at **477 Broad Street, Bridgeport, Connecticut**. The event archive has an event-specific scrollable list of linked song missions, recordings and released videos. Videos are not rehosted when only an external Drive link exists.
- The World mode visible label is **News** (internal `posts` mode retained temporarily to avoid changing legacy member feed routes or Travel defaults). `js/world-news-globe.js` renders headline metadata from the existing public `GET /v1/world/news`, 50 at a time with the existing opaque cursor. Loaded geotagged stories become amber pins. Tapping a pin locates the entry; tapping an entry locates its mentioned place on the globe. The existing mixed social feed remains below the news list during this compatibility phase.
- No full articles, third-party photos or newsroom branding are republished. Each headline opens a first-party discovery-record dialog; the news module never navigates to or fetches the publisher's site. GDELT attribution is preserved by the existing stream. The dialog explicitly states that licensed full text is not currently available, so the record is not represented as an in-app full article.
- There are **two different geographies**: news article location = location **mentioned** in extracted GDELT data, not a surveyed incident site; publication HQ = independently documented publisher headquarters. Do not substitute a story location for publisher HQ. The pending migration adds optional publisher classification, verified HQ coordinates, verification method/date and source URL to the existing `media_news_sources` domain registry. No publisher HQ positions are invented.
- The existing GKG process samples at most 100 articles per source file and retains one week, so this is **not all news articles worldwide**, and the client shows at most its paginated retrieved results. A true global historical news index needs ingestion capacity, regional partitions, publisher resolution and licensing review. GDELT FIPS codes are not ISO codes.
- The public news reading mode `WORLD_NEWS_READER_ONLY=true` currently yields an empty metadata feed by design; this mode is not a license for wholesale article text.
- This review branch should merge **after** #491 and pass its compatibility tests. No production deploy, direct publisher registration or account data mutation is part of this change.
