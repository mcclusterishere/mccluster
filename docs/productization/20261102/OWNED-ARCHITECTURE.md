# Own the mechanisms; retain one platform

This appendix belongs to the ONE whole-platform implementation assignment. Domain purchase, annual ownership, the bounded platform trial, retained site/data/control and module entitlements remain priorities. Research does not replace that work with four framework installations. This is a source-backed design and test plan, not a newly implemented chat-edit API.

Baseline: tested local backend ba06fed8438f041dab51234bf61d7fc64dbcb3f0. Control and Website Studio use vanilla ES modules. Native Expo/React is a separate surface; it does not justify a React/Next.js conversion of the website. `js/website-studio/contract.mjs` requires website-studio/v1, motion-portfolio template version1, exactly three uniquely identified tiles, kinds music/native_video/immersive360, at most one immersive tile, bounded fields and32KiB document size. `renderPlan` feeds both preview and public rendering. Control front-page preview uses the real page. Preserve both engines and their distinct schemas.

Core `core/src/compute/ollama-adapter.mjs` defaults to qwen3:8b, sends stream:false and advertises max_concurrency1. This is inspected source, not running-model attestation. A new chat presentation cannot create streaming, extra capacity or arbitrary page-schema support. No new inference server is needed for this slice.

## First owned slice: propose → preview → Apply → undo

Implement in existing chat/Studio host, not a new editor. Inspect the active chat caller/mount before wiring (existing chatfirst/deskchat/chatpage files are entry candidates, not proof of the active route). Keep proposal generation separate from save and publish. Use the existing bounded Core request path and authorization; if structured suggestion execution is not registered there, give Codex an exact caller/capability request. Do not invent a deployed RPC or start paid inference.

Proposed host envelope (design, not an existing endpoint):

```json
{
  "schema": "mccluster-tile-proposal/v1",
  "proposalId": "host-generated-unique-id",
  "runId": "host-owned-run-id",
  "target": { "projectId": "immutable-owned-project-id", "tileId": "tile-2" },
  "baseRevision": { "editor": 12, "studio": 4 },
  "baseDocumentDigest": "host-computed-sha256",
  "changes": { "headline": "A clearer heading", "body": "Reviewed replacement copy." }
}
```

The host binds identity/project/run/revisions/digest; model-supplied values cannot redirect that scope. First slice modifies headline/body of ONE existing tile, of any of the three currently supported kinds. It preserves tile ID/kind/order/count, template, media references, transition/playback/actions and all unselected fields. Unknown fields, empty changes, oversized proposal (>8KiB), invalid text or missing target are rejected, not silently stripped. Existing headline120/body2000 bounds and complete assertDocument validation still apply. New images/media selection must subsequently come from an authorized reference picker/resolver, never guessed model URLs/IDs. Arbitrary sections, scripts, HTML/CSS/component injection, purchase changes and new tile kinds are outside this contract.

1. Capture selected owned draft plus both revisions and a digest before requesting a suggestion. Send only the required scoped content; chat history/page text are untrusted input, not tool authority. Host owns one active run and discards late output after cancel/account/project changes. Current nonstreaming status is honest.
2. Validate the returned bounded changes, clone the captured draft, apply by stable tile ID, run assertDocument and the existing renderer/preview resolution. Show field-level before/after and real preview. Dirty local edits after capture invalidate the proposal or require a fresh reviewed proposal; never overwrite them quietly. No persistence occurs during generation/preview.
3. Explicit Apply alone calls current `PUT /v2/projects/{slug}/tiles` with the candidate document, expected_editor_revision=baseRevision.editor and expected_revision=baseRevision.studio. Recheck current session/target and host digest before sending; the server repeats Auth/M ownership and both CAS checks. The model cannot call save/publish. Backend rollout/feature flags remain separately gated.
4. On confirmed success, adopt returned revisions and add ONE undo entry with pre/post draft and tokens. On409 retain proposal/local edits and show conflict; no retry with a fresh token. On401/account switch stop applying and preserve only appropriately scoped draft state. Do not show saved on network error.
5. Lost response: read back draft/revisions and reconcile the exact candidate before declaring state; uncertain attribution stays uncertain. Current save has CAS protection, NOT a persistent proposal-id idempotency receipt. A repeated old token conflicts rather than duplicating history. Disable double-click locally, but do not claim durable exactly-once replay; a request-receipt ledger would be a separately reviewed backend enhancement.
6. Undo before save reverses local preview. Undo after a confirmed Apply is a NEW deliberate CAS save of the prior draft using the returned tokens, only if no intervening change; it creates new audit history rather than deleting it. A conflicting undo needs resolution. Publish remains its existing separate explicit action, with media/visibility/entitlement checks.

State model: idle→requesting→proposed→previewed→applying→applied; rejected/cancelled/failed/conflict/unknown-outcome are distinct exits. Chat UI state and selection do not enter the persisted site document. One host executor owns mutation, even if chat remounts or multiple views display the proposal.

## Acceptance and backend ownership

Claude implements the ES-module host integration, diff/preview, explicit Apply/Undo, accessible mobile states and deterministic proposal validation against this contract. Codex owns missing server capability registration, any durable idempotency enhancement and schema changes only when necessary; no migration is justified merely by displaying a proposal. Existing editor/Tile bridge tests remain the save authority.

Test plan (not yet executed for this new slice):

- Valid headline/body patch changes exactly one stable tile across each supported kind; preserves all other fields; before/after share the same renderPlan. Reject unknown schema/field/type, duplicate/missing ID, fourth tile, oversized data, markup execution, media/ownership/publish mutations.
- Preview makes no mutation/network tool call. Apply makes one save; double-click/rerender/late message cannot initiate another. Test actual SQL/HTTP CAS and both stale tokens, cross-user denial, disabled flag, expired session, account/project switch and downstream rollback.
- Dirty draft during generation, concurrent editor save, cancellation, interrupted response and lost save response preserve work and never report false success. Exercise undo as one transaction, including stale undo and reload.
- No auto-publication. Existing media checks and publish authorization still reject private/removed/unapproved resources. Admin Control rights remain separate from ordinary owner editing.
-390px no overflow; keyboard/focus/labels, reduced motion, diff readability, Apply/Undo status announcements. Real renderer and real-service acceptance must be recorded separately from fixtures. Keep existing144 editor,57 bridge and broader regression proofs intact.

## Later URL reconstruction boundary

Route an approved importer into the SAME structured draft/proposal pipeline. Before implementation, specify an authenticated owner-scoped fetch contract: HTTP(S) only; block credentials and private/loopback/link-local/metadata addresses for IPv4/IPv6; validate DNS and every redirect with rebinding protection; cap redirects, pages, concurrent requests, response bytes, decompression, image sizes and wall time; respect inaccessible/logged-in sites rather than bypassing controls. Exact limits become reviewed contract values, not unlimited defaults.

Parse inert content; exclude scripts, event handlers, active embeds and executable markup. Remote content cannot issue tools or supply authorization. No raw HTML execution. Keep origin URL, retrieval time, content hash and asset/license provenance; access to an image does not establish reuse rights. Distinguish borrowed layout ideas from copied text/assets. Preview and explicit acceptance precede persistence; publication remains separate. Fail closed on redirect/private-network cases and test malformed/oversized/compressed responses. Import does not migrate authentication, payments, databases, private pages or dynamic integrations. Broader page layouts require an explicit versioned schema and migration plan before claims of support.
